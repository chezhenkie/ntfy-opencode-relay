## Decisions

- 2026-11-10, row 7: one process with two supervised tasks. A second executable would duplicate the lock, config, log, and state ownership; the supervisor already isolates task failure. The MCP stdio server is a separate short-lived process, not a task.
- 2026-11-10, row 6: the current launcher is verified (logon shortcut, VBS, hidden task). A per-user service needs elevation or a wrapper and does not change the failure model, so the Rust binary slots in behind the same task. Linux uses a systemd user unit.
- 2026-11-10, row 8: state is bounded (topic cursors, last IDs, one routing hint per topic). Atomic JSON keeps parity with the Node state file and needs no migration; SQLite adds nothing until both directions share state. Since 0.11.0 the hint carries `last` and `pending` with timestamps; the old `pins` field is ignored.
- 2026-11-10, row 9: object-safe dynamic adapter. `async-trait` is a build-time proc macro and adds no runtime crate; the generated code is the same boxed future a hand-written version returns.
- 2026-11-10, row 10: the injected clock keeps the choice testable. A monotonic source prevents an NTP step or a manual clock change from extending a 60 s hold or a cooldown; replay windows compare server wall times and stay on wall.
- 2026-11-10, row 11: both text styles already exist in production. JSON POST carries UTF-8 titles without header encoding for outbound; header POST stays for relay acks so the phone output does not change. File uploads were always PUT with query metadata.
- 2026-11-11, row 3: a live `question` tool ask on OpenCode 2.2.7 produced one `form.created` frame with `location`, `form.sessionID`, `form.title = "Questions"`, `metadata.kind = "question"`, and one `string` field carrying the header in `title`, the question in `description`, and label/description options. `form.created` is therefore the notification source; the plugin's `tool.execute.before` hook is not available to the daemon.
- 2026-11-11, row 5: the shared service writes `~/.local/state/opencode/service.json` with `url`, `pid`, and `password`. The daemon reads it at startup, verifies the pid, and re-reads it after a transport error or HTTP 401; the client swaps only when the URL or password changed. GETs retry once inline. Writes refresh and re-post only on 401, because a transport error cannot prove the request was not applied. This keeps the no-child-process rule and avoids a fixed port. The private `~/.config/opencode/service.json` stays the explicit-server password source.
- 2026-11-11, row 1: the first capture (relay down 17 s) published only `GAP-PART-3` from a three-part session; the second capture with the forwarder (relay down 31 s) published `GAP2-PART-1`, `GAP2-PART-2`, and `GAP2-PART-3` in one push. The forwarder is an alternate feed, not a publisher: only the Rust daemon owns the ntfy token and the push; event-id dedupe keeps the two feeds from double-publishing.
- 2026-11-11, row 2: the stdio server is `ntfy-relay mcp`; the binary stays one build so the tool contract and the outbound policy cannot drift. OpenCode 2.2.7 connected it as server `ntfy` with one tool and rendered `ntfy_send_file`. `codemode: false` keeps the tool on the native tool list, matching the plugin, and the permission allow `ntfy_send_file` avoids a popup per send. The tool publishes directly, so a user-requested send is never dropped by the outbound queue.
- 2026-11-11, row 4: a child session is marked by `parentID` in `GET /api/session/<id>`. The gate child completed with no push; the parent turn text arrived. Suppression covers idle and error and cancels the child's buffered text, which is the plugin rule.
- 2026-11-12, row 12: the message API is the first server-side source that can replace the forwarder. A live query against the pinned session returned complete assistant messages with `id`, `time.completed`, and ordered text content, filtered by `type=assistant` and paged by cursor. Backfill is bounded to the seen window and the newest sessions per project, and publication stays at-most-once by marking the message id before the push. Gate 2026-11-12: the plugin was moved out and the relay stopped for 41 s while a three-line gate turn completed; the start logged `backfill cold=true sessions=20 messages=111 published=1` and the phone received `GATE-A`, `GATE-B`, `GATE-C` once. A second start logged `published=0`. The forwarder, ingest, registration, and token were deleted after that gate.

## Parked

- Remote wake on Linux hosts and long-sleep reconnect testing are not part of this migration.
- The ntfy Android client stays the F-Droid build; link safety remains a publisher rule.
