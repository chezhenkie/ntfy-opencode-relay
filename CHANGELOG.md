## 0.6.6

### Changes

* Question form answers no longer pass through a relay grammar. `/answer` followed by any text cancels the newest pushed form with that text as its reason, through `DELETE /api/session/{session}/form/{form}?message=...` (`session.form.cancel`). The desktop form closes at once, the assistant reads the free text as the result of its question, and asks again when the text is not enough. No code, no field number, and no option mapping in the relay. The push keeps the question and its options and ends with `Reply with /answer and your answer in your own words.` Spec 09 section 14.

## 0.6.5

### Changes

* Question forms can be answered from the phone. A pushed form is written to `ntfy-relay-forms.json` before its push and the push carries `Reply /answer <code> <field> <choice>, one message per field; /answer <code> send submits.` The field is the number the push printed; a choice field takes an option number, label, or value, a multiselect a comma list, a boolean yes or no, and a text field the rest of the message. Answers accumulate per form and are posted as `{"answer": {...}}` to `/api/session/{session}/form/{form}/reply`, which the live `/openapi.json` documents as `session.form.reply`. The form submits on the last field or on `send`; a 404 or 409 answers `already answered`, a 400 keeps the record and pushes the server reason. Spec 09 section 14; open work 10.12 closes.
* `/answer` is a native verb beside `/allow`, `/always`, and `/deny`, listed in `/help`, and reserved against the control table.

## 0.5.0

### Changes

* `ntfy-relay ensure` is the one-shot watchdog step. It prints `running pid=<n>` and exits 0 when the lock names a live relay image; otherwise it starts the daemon detached from itself, with stdout and stderr appended to `<root>\logs\relay-stdout.log` and `relay-stderr.log`, and waits up to 60 s for the lock. A child that exits first is reported at once, with the exit status. It writes one line to `<root>\logs\relay-ensure.log` per start or failure and nothing while the relay is alive. Spec 06.
* The scheduled task `ntfy-relay-watchdog` names `<root>\ntfy-relay.exe ensure` directly instead of `wscript.exe relay-watchdog.vbs`; the windowless binary needs no wrapper for a hidden start. `set-relay-watchdog.ps1` repoints the existing task in place and sets the working directory to the install root.
* The endpoint runtime file is named `ntfy-relay-endpoint.json`. It shared `ntfy-relay-control.json` with the command table, so a hard kill left a runtime file that the next start read as a table and refused; the relay now removes a legacy runtime file from the table path before it loads the table. The CLI and spec 12 follow the new name. Spec 12.
* The workspace and `package.json` move to 0.5.0.

## 0.11.0

### Changes

* Routing is derived, not stored. The per-topic pin is gone. `resolve_session` is replaced by a pure resolver in `rust\crates\inbound\src\routing.rs` that ranks a live snapshot: a one-shot pending target, then the previous target inside a 10-minute continuity window, then the session with the newest activity. Activity is the later of `time.viewed` (desktop use) and `time.updated` (any message). Child sessions are excluded. Ties break on running, then the previous target, then id, so one snapshot always resolves to one session.
* The failure this removes: a pin set on 2026-11-12 routed three phone texts on 2026-11-14 to that session while the desktop worked in a newer one, and only an `/auto` or an id-bearing `/to` could recover. A hint outside its window is now ignored, so no stored decision outlives the evidence.
* State: `pins` is replaced by `targets` with `last`, `lastAt`, `pending`, `pendingAt`. An old `pins` field is ignored and dropped on the first write; no migration step. Target rows are capped like topic rows.
* Commands: `/to` with no argument pushes numbered titles and keeps the list for 10 minutes; `/to 2` or `/to <title fragment>` sets the one-shot target. `/new` targets the session it creates. The pending target is consumed by the next accepted prompt or expires after 10 minutes. `/auto` clears it. No command takes a session id. `/sessions` prints numbers and titles; `/status` prints `target` instead of `pin`.
* Adapter: `SessionApi::session_signals` carries `time.viewed` and `parentID`; the default implementation keeps harnesses without those fields on `updated` only. `pin_session`, `get_session`, `PinRequest`, and `PinSink` are removed. The control capability names `session.pin` and `session.auto` stay as the command gates.
* Live-test fixes: continuity now yields when any other session was active after the previous prompt, so a 10-minute hint cannot hold a chat the desktop left. Hint timestamps come from the wall clock; the control engine's monotonic clock stays on confirm and cooldown arithmetic, so `pendingAt` is epoch milliseconds and the one-shot target actually fires. An opened-but-idle chat is not a target: OpenCode writes `time.viewed` on input, not on focus, and an empty TUI `/new` draft has no server session until its first prompt.

## 0.2.0

### Changes
